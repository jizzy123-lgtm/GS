# Development Session Log: 2026-04-04
**Topic:** Implementing and Debugging Expo Push Notifications End-to-End

This document is a comprehensive summary of all the configurations, roadblocks, and fixes we completed during this session to successfully implement native Expo Push Notifications in the React Native app.

---

## 1. Migrating to a Custom Development Build
Because standard "Expo Go" lacks the native Firebase libraries required for Push Notifications, we had to migrate the app into a custom Developer Build.
* Updated `package.json` to include the `expo-dev-client` library.
* Configured EAS (Expo Application Services) via `eas.json`.
* Ran the command `eas build -p android --profile development` to generate a `.apk` file containing all the necessary native Android Firebase libraries.

## 2. Firebase Cloud Messaging (FCM) Integration
To allow Expo to send notifications to Android devices, we fully hooked the app into Google Firebase:
* Downloaded the `google-services.json` from the Firebase Console and added it to the project root.
* Updated `app.json` to register the Google Services file:
  ```json
  "android": {
      "googleServicesFile": "./google-services.json"
  }
  ```

## 3. Expo Dashboard & Server Credentials
Initially, sending a notification using the Expo Push Tool resulted in an `InvalidCredentials` error. This meant Expo didn't have permission to use our Firebase project.
**The Fix:**
1. Navigated to **Firebase Console -> Project Settings -> Service Accounts**.
2. Clicked **Generate new private key** (downloads a `.json` file).
3. Opened the **Expo Credentials Dashboard** -> Android.
4. Uploaded that private key to the **FCM V1 credential** slot to authorize Expo.

## 4. Troubleshooting Network Visibility (The "Cannot connect to server" Error)
When a remote tester loaded the app via `--tunnel`, the UI loaded fine, but pressing "Login" threw an error and spun forever.
**The Root Cause:**
The React Native app's `api.js` was hardcoded to a private Tailscale IP (`http://100.82.99.76:8000`). While the Expo UI tunnel was sending Javascript over the public internet, the API calls themselves were trying to hit a Local/VPN address that the remote tester's phone physically couldn't reach.
**The Solutions:** 
* EITHER have the tester install Tailscale and log into the VPN network.
* OR expose the Laravel backend using `ngrok http 8000` and update `api.js` with the public ngrok URL.

## 5. Avoiding Common Testing Pitfalls
During testing, we ran into two distinct workflow errors that we learned to avoid:
* **The Web Browser Trap:** The developer accidentally opened the Expo tunnel link in Google Chrome instead of the custom mobile app. This threw a red `6000ms timeout exceeded` error and warned that Push Notifications cannot be tested on Web. **Lesson:** The Dev Client link MUST be typed exclusively into the Android App.
* **The Infinite Reload:** The tunnel gets stuck on the "Reloading..." screen because `ngrok` throttles massive Javascript files over slow mobile networks (it's sending 15-20MB on the very first load). **Lesson:** Patience on the first load, or restart `npx expo start --dev-client --tunnel -c` to generate a fresh connection. 

## 6. Laravel Backend SSL Error (cURL error 60)
Once the app was fully functional, attempting to create a new account threw a massive red banner: `cURL error 60: SSL peer certificate or SSH remote key was not OK`.
**The Root Cause:**
Laravel was successfully creating the account, but when it tried to ping Expo's API (`exp.host/--/api/v2/push/send`) to notify the Admins, the local Windows PHP/XAMPP server lacked the secure SSL certificates to communicate properly, causing it to crash.
**The Fix:**
* Modified the specific `Http::post()` call inside the Laravel backend code to use `->withoutVerifying()`, allowing the local development environment to bypass strict SSL checks. 

## Summary
By the end of the session, the pipeline was verified to be 100% functional:
1. Tester installs custom `.apk`.
2. App connects remotely via Expo Tunnel.
3. User Logs in successfully.
4. Terminal outputs `Got Expo Push Token: ExponentPushToken[...]`.
5. Expo Push Tool successfully beams the drop-down notification to the physical Android device!
