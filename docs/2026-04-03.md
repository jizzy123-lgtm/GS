## 1. Problem Identified: Not Connecting to Backend

### Root Cause
The `API_URL` was **hardcoded** inside every individual screen component file:

```js
const API_URL = "http://100.82.99.76:8000/api"; // duplicated in 10 files
```

This caused connection issues because:
- The Tailscale IP (`100.82.99.76`) was not always reachable.
- Any IP change required manually editing 10 different files.
- An empty and misnamed file `api.sj` existed at the project root (likely a typo for `api.js`).

## 3. Backend Connection Testing & Errors Encountered

### IP Addresses Tested (Chronological)

| IP Address | Port | Result |
|---|---|---|
| `100.82.99.76` | 8000 | `ERR_CONNECTION_TIMED_OUT` — Tailscale machine offline |
| `100.74.28.17` | 8000 | TCP connect failed — backend not running on port 8000 |
| `192.168.1.5` | 9000 | `Destination host unreachable` — wrong or changed IP |
| `100.120.159.52` | 9000 | `PingSucceeded: False, TimedOut` — Tailscale machine offline |
| `10.181.197.179` | 9000 | ✅ **Connected!** — Login successful |
| `10.58.186.81` | 8000 | CORS error — backend running but CORS not configured |
| `100.82.99.76` | 8000 | Current working URL (restored by user) |

### Key Errors

#### `ERR_CONNECTION_TIMED_OUT`
- **Cause:** The target machine was unreachable on the network (Tailscale offline or wrong IP).
- **Fix:** Change the IP in `api.js` to the currently active machine.

#### `Destination host unreachable`
- **Cause:** The device at `192.168.1.5` no longer has that IP (dynamic DHCP reassignment).
- **Fix:** Run `ipconfig` on the target device to get the current IP.

#### `ERR_FAILED` — CORS Policy Blocked
```
Access to fetch at 'http://...' from origin 'http://localhost:8082'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header
```
- **Cause:** Browser security blocked cross-origin requests.  
  This happens when the frontend (`localhost:8082`) and backend are on different domains.
- **Fix (Backend):** Set `CORS_ALLOWED_ORIGINS` or `CORS_ALLOW_ALL_ORIGINS = True` (or `*` in Laravel `config/cors.php`).
- **Frontend note:** Frontend cannot fix CORS — it must be fixed on the backend server.

#### `404 Not Found` on Dashboard
```
GET http://10.181.197.179:9000/api/requests → 404
```
- **Cause:** The Laravel backend has no route defined for `GET /api/requests`.  
  404 responses in Laravel do not include CORS headers, so the browser also reported it as a CORS error.
- **Fix (Backend):** Add to `routes/api.php`:
  ```php
  Route::get('/requests', [RequestController::class, 'index']);
  ```

#### Extra Space Bug in URL
```js
// BROKEN: space after http://
export const API_URL = "http:// 10.58.186.81:8000/api";
```
- **Cause:** Accidental space typed during manual edit.
- **Fix:** Removed the space: `"http://10.58.186.81:8000/api"`.

Git was installed but only accessible via Git Bash (`MINGW64`), not from PowerShell or CMD. This prevented Antigravity from running git commands directly.

**Workaround:** All git commands were run manually by the user in Git Bash (`MINGW64`).

### Commands Run

```bash

# Switch branch
git checkout laranjoMobile

# Force push (overwrite remote with local code)
git push -f origin APRIL_MOBILE_FINAL

# Fix "unrelated histories" error
git pull origin laranjoMobile --allow-unrelated-histories --no-edit

# Abort merge conflict
git merge --abort

# Create and push new branch
git checkout -b APRIL_MOBILE_FINAL
git push -f origin APRIL_MOBILE_FINAL
```

### Errors Encountered

| Error | Cause | Fix |
|---|---|---|
| `Repository not found` | Remote URL pointed to old repo `laranjoaprilgrace-star/GSO-App` | `git remote set-url origin` |
| `fetch first` (rejected) | Remote had commits local didn't have | `git pull` first |
| `refusing to merge unrelated histories` | Local and remote repos have no shared commits | `--allow-unrelated-histories` flag |
| `non-fast-forward` (rejected) | Branch tip behind remote | `git pull` then `git push -f` |
| Merge conflicts in `package.json`, `README.md`, etc. | Both repos had same filenames | `git merge --abort` then `git push -f` |
